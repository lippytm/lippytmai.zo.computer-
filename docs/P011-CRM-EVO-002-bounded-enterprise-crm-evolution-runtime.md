# P-011-CRM-EVO-002 — Bounded Zo CRM Evolution Runtime

## Purpose

Define the first safe runtime experiment for the Prompt #11 Enterprise Relationship Intelligence, Quality Telemetry, and Adaptive Evolution Fabric on `lippytmai.zo.computer`.

## Initial permitted workload

Run only the standard-library CRM Evolution engine and SQLite database using synthetic or public records to demonstrate:

- Business Ecosystem Passport loading;
- Quality Telemetry ingestion;
- review-only Fabric Hermes mission generation;
- sandbox-only evolution proposals;
- provider-certification checks;
- critical-gate release blocking;
- database integrity, backup, restore, correction, rollback, shutdown, and revocation.

## Runtime Experiment Passport

Every run must declare:

- human owner;
- repository commit and artifact hashes;
- environment and dependency versions;
- allowed data class and prohibited data;
- minimum permissions and secrets method;
- maximum cost and timeout;
- logging, monitoring, and correlation IDs;
- backup and restore plan;
- stop conditions;
- rollback, shutdown, credential revocation, and retirement;
- HumanApproval state.

## Prohibited data and actions

Do not use production customer records, private identity documents, medical or financial records, private keys, unrestricted clone memories, or confidential whistleblower evidence. The runtime cannot contact real people, broaden permissions, self-modify, move money, sign contracts, publish, or pass HumanApprovalGate.

## Environment separation

`development → sandbox → Q3 pilot → separate Q4 production decision`

Success in the sandbox does not authorize production synchronization or customer-facing operation.

## Current state

This is an architecture and Q3 experiment contract. It does not claim that the runtime or a live CRM connector is deployed.
